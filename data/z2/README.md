# `data/z2/` — Z2 architecture rule derivation: walkthrough

Added for the artifact package. It is a short guide to the Z2 chain from inputs to result.
The detailed provenance of each step is in [`MANIFEST.md`](MANIFEST.md); the rules are in the
protocol [`docs/protokolle/z2_protokoll_regelableitung.md`](../../docs/protokolle/z2_protokoll_regelableitung.md)
(frozen state in [`freezes/z2/`](../../freezes/z2/)).

> **Reading `MANIFEST.md`.** It is the living archive document from the thesis repository,
> copied unchanged. It was written step by step while Z2 was carried out, so its earlier
> sections show earlier states. In particular, the opening table still says that
> `eingaben/input_facts.json` is **missing** ("FEHLT NOCH"). That was true on 02.09.2026
> before task S2c-2. The file has been in place since then; it is listed in
> `eingaben/SHA256SUMS` and described further down in `MANIFEST.md`. The current state is this
> directory as it is.

All commands run from the repository root. Each one marked *tested* was run against this
package with the stated result. Commands that write do so into a scratch directory, except
where noted.

## 2 — Model runs and stored raw responses

`tools/run_z2.py` renders the one frozen prompt (it extracts the text from Anhang A of the
protocol), calls the model and archives each run in a slot:

| Cell | Slots | Files per slot |
|---|---|---|
| `k2_b1/` — `qwen2.5-coder:7b`, Ollama | `run0`, `run1`, `run2` | `prompt.txt`, `raw_response.json` (unchanged model response), `validation.json` (well-formedness Z2-W), `meta.json`, `run_manifest.json` |
| `k3_b1/` — `nvidia-nemotron-3-super-120b`, DigitalOcean | `run0`, `run1`, `run2` | same |

```bash
python3 tools/run_z2.py render                          # tested: builds the prompt, sends nothing, exit 0
python3 tools/run_z2.py selftest --workdir "$(mktemp -d)"   # tested: offline, exit 0
```

`python3 tools/run_z2.py run --condition <k2_b1|k3_b1> --slot <run0|run1|run2>` makes the model call. It needs
the endpoints and was **not** re-executed. The archived responses are the measured ones.

## 3 — Preparing the rating

`tools/prepare_z2_review.py` pools the proposals of the six runs and merges only
character-identical ones. It blinds the conditions, shuffles with the registered seed
`20260903`, and writes the empty sheet plus a separate key file.

```bash
python3 tools/prepare_z2_review.py --out "$(mktemp -d)"   # tested
```

*Tested result:* `zuordnungsschluessel.json` is byte-identical to `bewertung/zuordnungsschluessel.json`.
The fresh `bewertungsblatt.md` is the empty template. It differs from the archived sheet only
in the fields the assessor filled in.

> Always pass `--out`. Its default is `data/z2/bewertung/`, so a run without it would overwrite
> the completed sheet.

## 4 — Manual classification

One assessor filled in `bewertung/bewertungsblatt.md` blind, without opening the key: `kind`,
testability Z2-P, content Z2-G, assignment Z2-Z, deduplication Z2-R and borderline cases (protocol
§6). This step is human judgement; no tool reproduces it. The completed sheet is archived and
hashed in `bewertung/SHA256SUMS`.

## 5 — Mechanical evaluation

`tools/tally_z2_review.py` resolves the blinding and tallies every mechanically derivable figure
of protocol §7. It writes JSON to stdout.

## 6 — Overlap analysis

`tools/prepare_z2_overlap.py` built the matrix `bewertung/ueberlappmatrix.md`. For each of the
16 authored rule statements of `data/soll/architecture-rules.yaml`, it holds a machine
pre-finding and three empty author fields, which the author then filled in.
`tools/tally_z2_overlap.py --write` counts the author's decisions and merges the section
`ueberlapp_p5` into `bewertung/auswertung.json`.

Steps 5 and 6 together, *tested*. Both write `bewertung/auswertung.json` in place, and the
result must be byte-identical:

```bash
python3 tools/tally_z2_review.py > data/z2/bewertung/auswertung.json
python3 tools/tally_z2_overlap.py --write
git diff --exit-code data/z2/bewertung/auswertung.json   # no difference
sha256sum data/z2/bewertung/auswertung.json
# ed75e49d797dfda69931f390fef86818c0f4e6e63d42458da4cc41258e71043e
```

`python3 tools/prepare_z2_overlap.py --check` exits 1 with "weicht von der Neuerzeugung ab".
That is expected: it compares a fresh, empty matrix with the completed one. *Tested:* the
difference is exactly the 48 author fields (16 statements × 3).

All scripts in steps 3–6 use the Python standard library only.
